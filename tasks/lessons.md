# Lessons Learned

- 2026-08-22: Failure mode: treating the presence of Cloudflare secret binding names as proof that provider credentials were usable, while a background admin action returned success before inspecting its result; detection signal: no Twilio request and no delivery row despite a success banner; prevention rule: validate critical provider credentials with a cached authenticated health check, persist each attempt before provider validation, and never return background success without a durable job/attempt record.

- 2026-02-21: Initialized lessons log for remediation tracking.
- 2026-02-21: Route-action DB mocks must support both `prepare().first/run/all` and `prepare().bind().first/run/all`; otherwise tests can miss real query shapes and fail with mock-only type errors.
- 2026-02-23: When introducing stricter shared DB types, update dependent tests and typed query result casts in the same change; otherwise typecheck breaks on mock shape mismatches and `unknown` row types.
- 2026-02-23: Route-manifest integrity tests should use simple regex literals and validated filename normalization (`/\.tsx?$/`), because over-escaped patterns can silently invalidate the test harness.
- 2026-03-06: Notification helpers that aggregate external-send errors should redact recipient identifiers and return normalized `Error.message` strings; otherwise coverage runs drift between security expectations and runtime behavior.
- 2026-03-06: Debounced React component tests using fake timers need timer advancement wrapped in `act` (for example `await act(async () => vi.advanceTimersByTimeAsync(...))`), or state updates may never commit and the test will hang or assert stale UI.
- 2026-08-22: Optional webhook metadata comparisons must first prove the metadata is present; otherwise `null === null` can incorrectly suppress a normal response. Cover both provider-enriched and plain webhook payloads in regression tests.
- 2026-08-22: Never place Markdown backticks in a shell command argument; the shell treats them as command substitution. Write multi-line GitHub bodies with `apply_patch` to a temporary file and pass that file to the CLI.
- 2026-03-06: React Router route-module component tests should cast the assembled props object once at the render boundary when generated route prop types are stricter than the exercised scenario; otherwise `npm run typecheck` fails on test-only missing route metadata even though the runtime behavior is correct.
- 2026-03-06: Route tests that hand work to Cloudflare `waitUntil()` need to capture and await the queued promise before asserting background side effects, or happy-dom teardown can abort the work and make the test look like the side effect never happened.
- 2026-03-06: GitHub Actions only executes workflows from the repository-root `.github/workflows/` directory; nested `app/.github/workflows/` files do not run and can create a false sense that CI is enforcing checks when it is not.
- 2026-03-06: Failure mode: adding a workflow test that imports `node:sqlite` under the default `happy-dom` Vitest environment; detection signal: CI fails during Vite import analysis with "Cannot bundle built-in module `node:sqlite`"; prevention rule: mark Node-only workflow suites with `// @vitest-environment node` so Vitest runs them in the server environment.
- 2026-03-06: Failure mode: landing tests that depend on newer Node built-ins while CI is pinned to an older Node major; detection signal: local tests pass on a newer machine but GitHub Actions fails with "No such built-in module"; prevention rule: whenever tests or tooling rely on a Node built-in like `node:sqlite`, align the CI `setup-node` version with the minimum supported runtime in the repo.
- 2026-03-06: In Vitest auth/session tests, constructed `Request` objects do not reliably expose `Cookie` headers and redirect `Response` objects do not expose `Set-Cookie`; stub `request.headers.get("Cookie")` directly and assert session helper mocks instead of the response header.
- 2026-03-07: `crypto.randomUUID()` is typed as a UUID template literal in TypeScript, so test stubs must return a real UUID-shaped string or `npm run typecheck` will fail even though the runtime mock would work.
- 2026-03-07: Some route forms render visible labels without `htmlFor` or nested control associations, so route tests should query those controls by stable `name` selectors unless the task also includes an accessibility markup fix.
- 2026-03-07: In this Vitest `happy-dom` setup, `localStorage` is not always a full `Storage` implementation inside route-component tests, so tests that depend on visit-state keys should stub `localStorage` explicitly instead of assuming `clear()` and `removeItem()` exist.
- 2026-03-07: Test helper defaults can accidentally mask “missing configuration” branches; when exercising env-var guards, pass an explicit falsey runtime value like `""` or use a sentinel-based helper API instead of relying on `undefined` overrides that collapse back to defaults.
- 2026-03-07: After a PR merges, stop using that branch for new work. Detection signal: `origin/main` contains the merge commit but the working branch keeps accumulating follow-up commits. Prevention rule: branch from the latest `origin/main` for each new slice and open a new PR instead of pushing more commits onto a merged PR branch.
- 2026-08-22: Failure mode: accepting a dependency update generated under a newer npm without reproducing CI's peer resolution; detection signal: Node 22/npm 10 failed `npm ci` on the incompatible optional Workers types peers declared by React Router 7 and Wrangler; prevention rule: generate and clean-install dependency changes with the CI Node/npm toolchain, and use a targeted package override when one optional type-only peer is the sole incompatibility.
- 2026-08-22: Failure mode: using a hard-coded near-future event date in a poll-close success-path test; detection signal: the test began returning `Cannot create event for a date in the past` once wall-clock time passed that fixture; prevention rule: freeze time when date boundaries are under test, or use a deliberately distant date for unrelated success-path fixtures.
- 2026-08-22: Before declaring a PR ready, fetch the latest base branch and re-check mergeability after CI starts; a concurrently merged prerequisite can otherwise leave the PR conflicting and make already-fixed baseline failures appear current.
- 2026-08-22: Playwright can interact with server-rendered controls before React hydration completes; detection signal: a selection briefly changes but an initial effect restores the loader value. For hydration-sensitive controls, retry the action together with an assertion on the resulting enabled/UI state before continuing, and repeat the browser test in CI mode.
- 2026-08-22: A deployment workflow cannot consume build output from a separate CI runner unless that output is uploaded and downloaded explicitly. When deduplicating CI from deploy, retain a build-only step before Wrangler or transfer the verified artifact; detection signal is Wrangler reporting that `build/client` does not exist.
- 2026-08-22: Webhook handlers must treat body decoding as an untrusted boundary. Detection signal: a malformed POST without the expected form content type throws in `request.formData()` and returns 500 before authentication. Prevention rule: catch body-decoding failures, return a controlled 400, and include a non-form request in route regression tests.
- 2026-08-22: Browser tests for auto-submitting, visually styled radio controls should click the visible label and prove persistence after reload. Clicking the screen-reader-only input can be intercepted, and matching an internal React Router data URL couples the test to framework routing details instead of user-visible behavior.
- 2026-08-22: Failure mode: using the Jest-style `toStartWith` assertion without confirming it exists in this project's Chai-backed matcher configuration; detection signal: the focused test fails with `Invalid Chai property: toStartWith`; prevention rule: use `expect(value.startsWith(prefix)).toBe(true)` unless the repository demonstrates a custom prefix matcher.
- 2026-08-22: Failure mode: recommending an unchecked historical backlog item without reconciling work completed in another task; detection signal: the user reports that the production validation already happened elsewhere; prevention rule: treat old unchecked items as leads only, verify current production/PR evidence or ask about cross-task completion before calling one the next priority.
- 2026-08-22: Browser-test fixtures must satisfy production domain invariants; negative sentinel IDs can make otherwise-valid boundary checks fail only in E2E. Use reserved high positive IDs for entities whose production IDs are positive, and clean them up explicitly.
- 2026-08-22: Failure mode: expanding an existing multi-purpose UI fixture with extra rows and invalidating its singular text assertions; detection signal: Testing Library reports multiple matches for an unrelated status such as `Active`; prevention rule: cover new display-state matrices in a dedicated focused test so established interaction fixtures retain their original cardinality assumptions.
